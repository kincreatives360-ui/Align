## 3. Inspector (right panel → Visual tab) + all control surfaces

### 3.1 Architecture verdict: **hybrid — declarative for template params, hand-written for style**

Two clearly different mechanisms coexist:

**(a) Template parameters are declarative.** Each template (and each shared modifier group) is a data array of param descriptors; `paramControl(app, p)` dispatches on `p.type`:

```js
function paramControl(app, p){
  const path = 'params.' + p.key;
  if (p.type === 'range'){ … const r = slider(app, p.label, path, {min:p.min, max:p.max, step:p.step, fmt}); … }
  if (p.type === 'seg')    return seg(app, p.label, path, p.options, {rebuild: p.rebuild});
  if (p.type === 'select') return select(app, p.label, path, p.options);
  if (p.type === 'toggle') return toggle(app, p.label, path, {rebuild:true});
  if (p.type === 'color')  return color(app, p.label, path);
}
```

Schema sources: `COMMON_PARAMS` (`count` 1–80, `speed` .1–3, `dir`), `MOD_GROUPS` (bend, depth, shape, pose, tilt, disp, transform, easing, anim — each with `{key,label,type,min,max,step,def,options,unit,percent,hint}`), each template's own `params: [...]`, and `FLARE_PARAMS` for `kind==='flare'`. `controlGroups(t, P)` assembles them into collapsible groups and **conditionally filters** them (e.g. the `anim` group collapses to one row until `animIn` is on; `easing` shows only `hold/ease` unless `motion === 'stepped'`). A descriptor example:

```js
{key:'cardSpin', label:'Card spin', type:'range', min:-3, max:3, step:1, def:0, unit:' turns', hint:'each card turns round its own centre'}
```

**(b) The style/visual inspector is hand-written.** `visualPanel(app, box)` is one long function that calls `section(...)` + `slider/select/seg/toggle/color/text` with **literal state paths** (`'style.glass.width'`), literal min/max/step, and conditional children computed from current state (`L.mode === 'glass' ? slider(...) : null`). There is no style schema/table anywhere in the codebase — the "schema" is the code itself. Defaults live separately in `state.js` `BASE_STYLE`.

**Shared control primitives** (`ui.js` lines 64–155) — all write through the same two functions:

| Primitive | DOM | Write pattern |
|---|---|---|
| `slider(app,label,path,{min,max,step,fmt,unit,percent})` | custom `div.sl` with `.fi` fill, `.kn` knob, `.vl` value text, `role="slider"` | `pointermove` → `setV()` → `app.set(path,v)` (no history); `pointerup` → `app.commit()`. **Shift+drag = 15 % fine control**, arrow keys ±step (Shift ×10), **double-click = type exact value** |
| `seg(app,label,path,options,{rebuild,locked,onLocked})` | `div.sg` of buttons, active gets `.on`, Pro-locked get `.pro` + crown | click → `app.set(...); app.commit(); draw(); if(o.rebuild) app.rebuild()` |
| `toggle(app,label,path,o)` / `toggleEl` | `button.tg` `role="switch"` | click → `app.set + app.commit + classList.toggle('on')` |
| `proToggleEl` | same but `.tg.pro`; on free plan opens the Pro modal instead of switching | `app.proNeeded(why)` |
| `select(app,label,path,options,o)` | native `<select class="sel">` | `onchange` → `set` (coerces to number if current value is numeric) + `commit` |
| `color(app,label,path)` | `<input type=color>` + hex `<input class="txt">` | `oninput` → `set` (live), `onchange` → `commit` (one undo entry per colour pick) |
| `text(app,label,path)` | `<input class="txt">` | `oninput` → `set`, `onchange` → `commit` |
| `section(app,id,title,sub,{open,pro,isNew,soon,flat,toggle,action},...kids)` | `div.sec > div.sh` (title `.t1`, subtitle `.t2`, optional header toggle, optional action button, chevron) + `div.sb` body | header click flips `.open` and updates `app.ui.open/closed` |

`getPath`/`setPath` are dotted-path accessors:

```js
export function setPath(o,p,v){ const ks = p.split('.'), last = ks.pop(); const t = ks.reduce((a,k)=>a[k]??={},o); t[last]=v; }
```

## 4. Layer system — **there is no layer list**

Findings (verified by grepping the whole `js/` tree for `layer`):

- **No layer stack, no per-layer visibility, no per-layer selection, no z-order UI.** The only "layers" in the codebase are *inside* templates: e.g. `choreo-f.js` param `{key:'layers', label:'Layers', type:'range'...}` (how many depth planes a template fans out into) and shader/blur-layer internals in `renderer.js`/`faces.js`. `I.layers` (the stacked-diamond icon) is defined in `ui.js` line 26 and never referenced.
- **What plays the role of "layers" is the media list**: `state.media.images` is an ordered array — "images: your media in **card order**" (`state.js` line 63). The engine assigns `media.items[i % items.length]` to card *i* (`engine.js itemFor`), so array order = card order (unless `media.order === 'scatter'`, which applies a seeded shuffle via `orderFor`).
- **Media panel operations** (`mediaPanel` + `App` methods):

| Operation | Mechanism | Code |
|---|---|---|
| Add | `#fileImgs` picker, window drop, paste, or Library "Add N to project" | `App.addMedia(files)` / `addLibrary(items)` → `state.media.images.push(m)` → `commit()+rebuild()+queueThumbs()` |
| Reorder | HTML5 drag between grid items; drag payload key `'text/x-ac'` carries the source index | `it.ondragstart = e => e.dataTransfer.setData('text/x-ac', String(i))` … `it.ondrop = … app.moveImage(from, i)` → `L.splice` + `commit()+rebuild()` |
| Remove one | `×` button on each item | `app.removeImage(id)` → filter + `forget(id)` + `commit()+rebuild()` |
| Remove all | "Remove all" button | `app.clearImages()` |
| Hide | **Not possible** — there is no visibility flag; removing is the only way to take an item off the cards | — |
| Order mode | seg `media.order` = `in` / `scatter`; Reshuffle button bumps `media.seed` | line 281–282 |

- **Selection on the canvas: none.** You cannot click a card on the canvas to select it; the canvas is a WebGL surface with no pointer handlers (`#wrap` has none). The only "selection" UI is:
  - Template selection → `.tpl.on` class on the thumbnail card (plus `.dot-on` dot on the active category header);
  - Hover on a thumbnail → `app.hoverThumb(id)` renders that template's preview **live** in the thumbnail (`thumbTick` advances its time from `hoverStart`), `mouseleave` stops it;
  - Rail/tab/section active states (`.on` / `.open` classes).
- The `#zones` / `#safe` overlays and the timeline are the only things drawn over the canvas.

## 5. Timeline — a single scrubber, **no keyframes, no tracks**

`#timeline` is built in `App.chrome()` (lines 699–708) with exactly three children:

```js
this.scrub = h('div', {class:'scrub'}, h('div',{class:'tr'}), h('div',{class:'fi'}), h('div',{class:'hd'}));
this.timeEl = h('div', {class:'time'});
this.tlPlay = h('button', {class:'ib ghost', onclick: () => this.togglePlay()});
$('timeline').append(this.tlPlay, this.scrub, this.timeEl);
```

| Element | Role |
|---|---|
| `.scrub .tr` | static track bar (CSS `background:var(--panel3)`) |
| `.scrub .fi` | progress fill — `updateTimeline()` sets `children[1].style.width = (f*100)+'%'` |
| `.scrub .hd` | playhead — `children[2].style.left = (f*100)+'%'` |
| `.time` | `` `${t.toFixed(2)} / ${len.toFixed(2)}s` `` |
| `#tlPlay` | play/pause (mirrors toolbar play button) |

Scrubbing (quote):

```js
this.scrub.onpointerdown = e => {
  this.scrub.setPointerCapture(e.pointerId); const was = this.playing; this.playing = false;
  const go = ev => { const r = this.scrub.getBoundingClientRect();
    this.T = Math.max(0, Math.min(1, (ev.clientX - r.left)/r.width)) * clipLength(this.state) * .9999;
    this.dirty = true; };
  go(e); this.scrub.onpointermove = go;
  this.scrub.onpointerup = () => { this.scrub.onpointermove = null; this.playing = was; this.updateChrome(); }; };
```

**Time is a scrub over a procedurally animated template — there is no keyframe system of any kind.** Evidence:

- The clock is one scalar `app.T` advanced by rAF: `if (this.playing){ this.T += dt; this.dirty = true; } … if (this.T >= len) this.T = this.T % len;` (`loop()`, lines 612–625).
- The clip length comes from `clipInfo(state)`: `loop = duration(template)/speed`, `clip = export.duration || loop`, and with `export.seamless` on, `rate = loops*loop/clip` — i.e. motion is time-scaled so a whole number of loops fits the chosen duration ("Motion runs at 1.32× so 2 loops fit exactly").
- Each frame is a pure function of `(state, T)`: `draw(T){ const desc = buildFrame(this, T, W, H); syncLabels(this,W,H,T); this.renderer.render(desc); }`.
- Nothing in `state` stores per-time values; the only time-shaped data are loop parameters (`speed`, `dir`, `hold`, `ease`, per-template `dur`) and the text/logo in/out animation envelope (`animAt()` in engine.js, computed from `clipLength`).
- Timeline updates are pushed from `commit()` and from the rAF loop whenever `dirty` (`updateTimeline()`), so the playhead moves every rendered frame.

## 6. State update pattern — central setter, dirty flag + rAF redraw, **one undo entry per gesture**

Two central functions (`main.js` 215–218):

```js
set(path, v){ setPath(this.state, path, v); this.changed(); }
changed(){ this.dirty = true; clearTimeout(this.saveT); this.saveT = setTimeout(() => save(this.state), 400); this.queueProjectSave(); }
commit(){ this.history.push(this.state); this.changed(); this.updateTimeline(); this.trackChanges(); }
```

**Exact flow of a slider drag → canvas redraw:**

1. `pointerdown` on `div.sl` → `setPointerCapture`, record `startV`.
2. Each `pointermove` → `setV(v)` clamps/quantises to `min/max/step`, and `if (v !== get()){ app.set(path, v, o); show(); }`.
   - `app.set` writes the dotted path into `this.state` and calls `changed()` → `this.dirty = true` + debounced localStorage save (400 ms) + debounced project autosave (1200 ms via `queueProjectSave`).
   - `show()` updates **only this control** (fill width, knob position, value text) — a targeted DOM update, no panel rebuild.
3. Next `requestAnimationFrame` tick: `if (this.dirty){ this.draw(this.T); this.dirty = false; this.updateTimeline(); }` → `buildFrame(state,T,W,H)` → `renderer.render(desc)` (WebGL). **The canvas never redraws from `set()` directly — the dirty flag feeds the single render loop.**
4. `pointerup` → `app.commit()` → `history.push(this.state)` (one JSON snapshot for the whole drag), `changed()`, `updateTimeline()`, `trackChanges()` (analytics: diffs `flat(params)`/`flat(style)` against the last commit and emits `controls_changed` with the changed keys).

**Undo/redo:** `History` (`state.js` 115–131) keeps up to 80 JSON snapshots of the whole state (media images stored as ids only, re-resolved on `step`), deduped (`if (this.stack[this.i] === snap) return`). `undo(d)` swaps `this.state = upgrade(s)` and then `changed()+layout()+rebuild()`. `⌘Z / ⇧⌘Z` and the header buttons call it. Because `commit()` is only called on *change events* (`pointerup`, `onchange`, button clicks), **an undo step = one committed gesture**, not one input event. Colour/text inputs follow the same rule: `oninput → set`, `onchange → commit`.

**When is the panel rebuilt?** `rebuild()` is *not* automatic per keystroke. It is called explicitly when structure changes — `if (o.rebuild) app.rebuild()` on segs/toggles/selects flagged `rebuild:true` (bg mode, glass mode, lens mode, resolution, fps, aspect…), on template select, preset apply, media changes, tab/rail clicks, and after undo:

```js
rebuild(){ const keep = ['left','right'].map(id => $(id).scrollTop);
  leftPanel(this); rightPanel(this);
  ['left','right'].forEach((id,i) => $(id).scrollTop = keep[i]);
  this.updateChrome(); }
```

Scroll position is preserved across full rebuilds. `updateChrome()` refreshes the toolbar/rail/play-button/undo-disabled states. **There is no subscribe/event-bus mechanism anywhere** — refresh = "someone calls `rebuild()`" or "the dirty flag makes the loop redraw".

## 7. Rendering approach (DOM)

- **Imperative hyperscript**, one 10-line helper: `h(tag, attrs, ...kids)` uses `document.createElement`, handles `class`/`html`/`style`/`on*`/attributes, flattens kids, appends text nodes. Template literals appear only for SVG icon strings (`const svg = (d,s=16) => \`<svg …>${d}</svg>\``), a few `innerHTML` injections (`$('undo').innerHTML = I.undo`), and `pre.embed-code`.
- **No framework, no VDOM, no diffing.** Panels are built fresh each time (`el.innerHTML=''` then `h(...)` trees) — `leftPanel`/`rightPanel` are pure functions of `app.state` + `app.ui`.
- **Refresh strategies actually used:**
  1. *Targeted*: slider `show()`, segment `draw()` (rebuild only its own buttons), palette swatch re-render (`rightPanel(app)` after a palette pick), section open/close via `classList`.
  2. *Full panel rebuild*: `rebuild()` — used liberally; scroll positions restored.
  3. *Canvas*: single rAF loop gated by `this.dirty`; `layout()` (fit + backing-store size, quality tiers draft/auto/max with DPR caps) sets `dirty=true`.
  4. *Thumbnail grid*: a time-sliced queue — `thumbTick` renders up to 10 ms per frame from `thumbQueue`, and hovered thumbnails re-render continuously with animated time.
- Sections remember open/closed in `app.ui.open/closed` Sets so a rebuild restores the accordion exactly as left.

## 8. Interactions

### Files in (three routes, all → `App.addMedia`)
- `#fileImgs` change (picker from the Media dropzone or `+` button), `accept="image/*,video/*" multiple`.
- Window-level `dragenter/dragover/drop` with a counter `dn` driving `#drop` (`.on`); `drop → addMedia(e.dataTransfer.files)`.
- `paste` → `addMedia(clipboardData.files)`.
- `addMedia` decodes first (`M.downscale` for images, `M.loadVideo` for video), stores blobs in IndexedDB (`S.putMedia`), pushes `{id, kind, name}` into `state.media.images`, then `commit+rebuild+queueThumbs`; failures surface as toasts. Videos are Pro-gated on free plans (`files.filter(f => M.kindOf(f) !== 'video')` + `proNeeded`).
- Project files: `#fileProj` change → `App.openProject(file)` (`.aligncanvas.json`, videos left out by design).

### Canvas pan / zoom / fit
- **There is no pan and no zoom.** The preview is always *fit*: `previewSize()` computes the largest box of the current aspect inside `#view`'s padded box; `layout()` writes it to `#wrap` and sizes the canvas backing store (`k` = quality tier, capped at 900/2200/3000 px by `frame.preview`).
- Fullscreen: `F` or toolbar → `#wrap.requestFullscreen()`, re-fit on `fullscreenchange`.
- A `style.camera.zoom` slider exists, but that zooms the *composition* inside the frame, not the viewport.
- The composition zooms out automatically for narrower aspects: *"a narrower frame than the template was designed for zooms out to keep the whole composition in view"* (engine.js).

### Safe zones / guides — two separate overlays
1. `#safe` — composition guides (thirds + inset dashed border via CSS `::before/::after`), toggled by toolbar **Guides (G)** or key `G` (`$('safe').classList.toggle('on')`). Never exported.
2. `#zones` — social safe areas; `showZone()` sets `z.className = 'zones' + (f.zone && f.zoneShow!==false ? ' on z-'+f.zone : '')`. CSS defines `z-reels` (13% top / 24% bottom / 13% right, labelled "Reels / TikTok safe zone"), `z-story` (13%/18%), `z-feed` (3.125% sides, "Profile grid shows 3:4"). Toggled by the `Safe zone guides` toggle in Export → Social presets (`frame.zoneShow`).

### `tour.js` — first-visit guided tour (65 lines)
- A single `STEPS` array of 9 entries, each `{title, text, sel?, rail?, last?}`. Targets are real selectors: `#left`, `#rail [data-k="media"]`, `#view`, `#timeline`, `#right`, `#left .bigtab:nth-child(2)`, `#rail [data-k="project"]`, `#exportTop`. ### `brand.js` — brand kit persistence (Pro)
- Shape: `EMPTY = {colors:[], head:'', body:'', logo:'', fonts:[]}` under `localStorage['ac-brand']`. **Blobs live in IndexedDB** (`store.js`, kinds `'logo'`/`'font'`); localStorage only holds ids — quoted from the header comment: *"The logo and any font files are blobs in IndexedDB (store.js, kinds 'logo' and 'font'); localStorage keeps only their ids."*

- `addLogo(file)`: downscales to 1024 px on the long side, re-encodes as PNG (transparency survives), stores as `logo-xxxxxxxx`.

## 10. Rebuild notes / gotchas for a production rebuild

1. **Two-tier control system**: keep the declarative param schema (it powers 100+ templates, per-group resets, modified-state markers, and analytics diffing) but consider *also* making the style inspector declarative — today it is 200 lines of hand-written literals with conditional children scattered through `visualPanel`.
2. **Conditional controls are computed at build time**, so any state change that alters which controls exist must call `rebuild()` (`rebuild: true` option) — a naive framework port that only re-renders values will break (e.g. lens `mode` changes the whole control set).
3. **Commit granularity matters**: `set` (continuous) vs `commit` (gesture) is what makes undo feel right and makes drag operations cheap. Preserve it.
4. **No keyframing**: the timeline is a loop scrubber. If the rebuild needs keyframes, that is net-new design, not parity.
5. **No layer stack / no canvas selection**: parity means media-order-as-card-order + a thumbnail/template selector; anything more (click-to-select a card, visibility toggles) is a feature addition.
6. **Full-panel rebuilds with scroll preservation** are the refresh primitive; a rebuild should keep `scrollTop` for both panels and keep accordion open/closed state in UI state, not in the DOM.
7. Pro gating is woven into the controls themselves (`locked` option on `seg`, `proToggleEl`, `inert` wrappers, build-time clamping in `exportPanel`) — a rebuild needs a single gating layer rather than these ad-hoc checks.
